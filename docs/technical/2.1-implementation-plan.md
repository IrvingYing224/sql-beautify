# SQL Beautify 2.1 实施计划

状态：版本调整中

设计：[`2.1-remediation-design.md`](2.1-remediation-design.md)

目标：所有波次完成后统一生成 `2.1.0` 发布候选，不进行中间版本发布。

## 执行规则

- 按下列顺序串行执行波次；同一 worktree 的 build/test 绝不并行。
- 每波先补/调整失败回归，再实现，再运行 targeted gate、typecheck 和 `git diff --check`。
- 每波完成一次只包含该边界的本地提交；提交格式遵循仓库中文 Conventional Commit 规则。
- 审计报告、设计和本计划先提交，之后才允许修改实现。
- 已固定的保守决策直接执行，不等待用户确认。只有外部 push/release、删除用户数据或改写历史会停止。
- 如发现报告断言与代码/实测冲突，以复现证据为准，同步修正文档并继续执行。
