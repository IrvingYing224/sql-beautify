## 1. 目标与完成边界

本轮把 2.1 发布后的全部审计发现纳入一个整改范围，最终只形成一个 `2.2.0` 发布候选。
中间波次允许创建可回退的本地提交，但不得修改成可发布的小版本，不得 push、打 tag、创建
GitHub Release 或触发发布 workflow。

“纳入整改”不等于无条件接受审计结论。每一项必须得到以下一种终态：

1. 用失败回归或可重复测量证实，并由代码、测试和文档完成修复；
2. 证实属于有意契约或不可达防御路径，用测试和维护文档固定理由；
3. 用反例推翻，记录复现方法和撤销依据，不留下“待验证”。

以下安全边界不得为减少代码或提高性能而放宽：

- lexer 继续拥有 token/source span，renderer 继续是格式化空白和 keyword case 的唯一写入者；
- comment、string、quoted identifier、parameter、dialect literal 与 opaque/verbatim slice 保持逐 code-unit 无损；
- public result、worker message、transaction 与 host commit 的不可信边界继续完整验证；
- document、range、multi-selection、worker 和 experimental DDL 继续 fail closed、all-or-nothing；
- source-map 的 source/output 双单调和 token equivalence 保持不变；
- 未建模或 malformed 语法只按可证明边界 preserve，不通过局部单词或正则猜测结构；
- 只保留现有两个公开值 API 入口，不公开 parser、layout、transaction、executor 或 internal artifact。

## 2. 固定设计决策

### 2.1 Parser 复杂度与保护通道

unsupported-clause 证明不得通过嵌套 speculative parse 重复计算同一事实。parser context 增加请求级
trial cache 与工作量预算：

- trial API 必须接收可序列化的 purpose/range/mode key，禁止继续用无法缓存的匿名 closure 作为唯一身份；
- 同一 source、dialect、mode、purpose、range 和 nesting depth 的 trial 最多执行一次；
- trial work units 按访问的 leaf range 记账，超过与输入线性相关的预算时返回稳定的
  `SYN_PROOF_BUDGET` warning 并 preserve 已证明边界；
- regression 主门使用 trial invocation/leaf-visit 计数的线性上界，另保留宽松墙钟灾难门；
- 不缓存 trial 构造出的 CST，只缓存“完全结构化/不能证明”布尔事实，避免节点 identity 与诊断回滚污染。

已复现的嵌套 `QUALIFY` 样本必须从 depth 22 的 86.5 秒降到线性有界，并保持 capability identity。

`normalizedWord` 只允许 structural code word。quoted identifier、parameter、string 等 protected callee
可以成为普通 function-call 的 lossless callee，但不得参与 collection-name keyword 判定；非法 callee
按语法错误恢复，不得产生 `SYN_INTERNAL_INVARIANT`。

### 2.2 Layout 资源耗尽与对齐

资源耗尽与 artifact 损坏必须分开：

- 可预期的 parser/layout depth、indent、generated-column 或 doc-node budget 耗尽返回 warning + preserve，
  不再伪装成 `LAYOUT_COMPILE_ARTIFACT` internal error；
- artifact provenance、非法 gap、越权 emission 等真实契约破坏仍返回 error + failed；
- 深层 CASE、括号、子查询使用同一资源耗尽分类和安全提示。

alignment 第二遍继续保留。修复采用以下规则：

- 从 `space` 升级的 `pad-to-column` 必须至少生成一个显示列，AS/comment 双重对齐不能把词法分隔压成 0；
- alignment target 在注册前同时受 `maxAlignWidth` 与 layout resource budget 约束；合法配置超出当前请求预算时
  跳过该 target，不 poison 整个 plan；
- 对齐候选使用最终会同时生效的 target facts 计算，避免第一遍 comment column 与第二遍 AS 位移互相覆盖；
- `commaStyle=trailing` 的 source-order 冲突仍按 ADR 0002 局部降级为 leading，但产生一个去重后的
  `LAYOUT_COMMA_FALLBACK` information diagnostic，并在 README 配置说明中披露。

### 2.3 Trivia ownership 与 renderer suffix

comment binding 增加明确的左右成员行约束：

- comma-first 的 `, /* comment */ item` 只有左成员也在逗号同行时才绑定左成员，否则 leading 到右成员；
- 位于前一语句后、后方有空行的 footer comment 归前一 statement；
- statement 最后一个 code leaf 后、terminator 前的独立行注释归 trailing/dangling，不标成 leading；
- 每个 comment 仍只允许一个 binding，文本不因 ownership 修复而重排。

renderer 对 pending suffix 队列逐项维护 physical-line 状态。line comment 后若还有 suffix，必须先换行；
测试需要证明该路径可达，若 canonical planner 永远不能构造该队列，则删除死分支而不是保留未测行为。

### 2.4 Lexer 与显示宽度

registry keyword 是 ASCII 语法事实。identifier keyword 判定改为 ASCII-only fold；任何包含非 ASCII
code point 的 identifier 不得通过 ECMAScript Unicode `toUpperCase()` 折叠成 keyword。

其余词法项按方言处理：

- generic/postgresql `::` 与 parameter 边界不能把第二个 `:` 后内容误判为 parameter；
- MySQL `@@name` 作为一个有界 system-variable protected leaf，不拆成 unknown + parameter；
- Hive `${...}` 使用有深度预算的 brace scan，支持嵌套并在未闭合时 lossless preserve；
- U+2028/U+2029/NEL 不作为 SQL physical newline；用契约测试固定，不修改 line-comment 终止规则；
- PostgreSQL ASCII identifier 先走无分配快路径，Unicode code point 才进入 property lookup；operator
  按首字符分桶；ASCII keyword candidate 不分配临时 uppercase string。

display-width 数据升级到实施时可验证的最新稳定 Unicode 版本，并钉输入 SHA。ZWSP、SHY、ZWJ、
variation selector、combining mark 等 default-ignorable/zero-width code point 按编辑器显示事实计 0；
新增 emoji 宽度按新版数据计 2。tab width 从请求级 render environment 读取：VS Code provider/command
使用编辑器 `tabSize`，public value API 保持兼容默认 4，不新增公开 format option。

### 2.5 Source map 查询

renderer 构造的 source map 增加模块私有 canonical proof 和一次性二分索引。`mapSourceOffset`：

- canonical map 命中 proof 后不再逐查询 clone/冻结/全量重验；
- 非 canonical 输入仍走完整 snapshot validation，维持测试与不可信调用的 fail-closed 行为；
- 查询改为按 source start/end 二分，gap affinity 语义不变；
- 同一 selection 的 anchor/active 查询共享 index，不能为每个 affinity 重建结构。

空 entries + 非空 source 的 left/right affinity 保持 `null`，因为没有可证明 source-derived anchor；
该审计项以契约测试关闭，不猜测映射位置。

### 2.6 Production invariants

2.1 的“每次 parse 运行测试级全量 oracle”决策由本设计替代。public API 不接收外部 CST，canonical
CST 只能由 node factory 与 parser 创建，因此生产路径采用分层证明：

1. node factory 在构造时验证局部 shape/range 并写入私有 provenance；
2. parser 完成后执行 O(1) provenance/root coverage 检查；
3. structural-index 的单次遍历成为跨节点 marker/operator/separator/capability/span 的唯一生产验证；
4. worker result、public result 与 host commit 边界继续完整 snapshot validation。

以下内容移到 tests/debug-only validator：独立 token-table expected oracle、约 55 个 misuse exception probes、
每节点 marker closure 全 range 重扫。validator 仍可由测试直接调用，并继续覆盖伪造、mutation、descriptor、
prototype、range 和 registry misuse。

重复 helper 收敛到单点：`validateSubRange`、`CLAUSE_KINDS`、frozen data array、空 range→span、operator
occurrence、alias/AS facts。目标不是机械减少行数，而是让每条事实只有一个生产 authority 和一个独立测试 oracle。

### 2.7 Range、selection 与 VS Code 入口

全选与跨 statement range 采用显式 statement-sequence 语义：

- 唯一非空选区覆盖完整 document 时直接使用 document target；
- 选区若精确覆盖连续完整 statements，validator 返回 statement ranges，executor 以 document-mode
  格式化该 slice 或逐 statement 计算后原子合成一个原 target result；
- 半条 statement、跨 opaque boundary 或无法证明的 trivia ownership 仍拒绝；
- 原 selection direction 与 target identity 保持，任何子结果失败则原 target 整体拒绝。

`alt+shift+f` 不再覆盖 VS Code 内建 Format Document：删除该默认 keybinding，保留命令面板命令；
README 给出通过 `editor.defaultFormatter`、Format Document/Selection 与用户自定义快捷键的标准入口。

配置读取返回 discriminated success/failure，不再把非法值与 editor state 混成 `null`：

- provider/format-on-save 发布一次 `CFG_*` diagnostic，不弹窗；
-显式命令按具体 key 提示并给出允许范围；
- safe message 以 code + validated option key 为单一事实来源。

命令反馈按 stale/range/input-limit/worker/config/edit-rejected/unsupported 分类。runtime message 提供
`en` 与 `zh-cn` 资源；未知 locale 使用英文。DDL stale/edit rejection 不再误报成“超出 experimental subset”。

成功 edit 后的旧诊断 span 用 target source map 或明确的 edit delta 映射；无法证明时才折叠到文档级。
`copySafeDiagnosticReport` 的 cancel/stale 显示 information message。文本变化监听先过滤 supported language；
设置标题统一为 SQL Beautify，非 SQL 编辑器通过 command `enablement` 隐藏不适用命令。删除 VS Code 1.90
下冗余的 `onCommand` activationEvents，并在 README 说明 `hive-sql` language id 由第三方扩展提供。

### 2.8 Executor 与 worker protocol

worker protocol 先读取 `kind` 再按单一 schema 验证，并新增有界 negative response：

- 可解析 identity 但 payload 非法时返回 `protocol-error`，host 立即以稳定 diagnostic 失败；
- runtime digest mismatch 单独识别为 `ADAPTER_WORKER_RUNTIME_MISMATCH`，立即 retire，不等待 60 秒；
- 完全无法解析且无法安全回显 identity 时 worker 退出，由 host crash path 立即收敛；
- producer 在 batch/worker 出口把 debugEvents 截断到共享上限，并发出一个静态 truncation event；
- `responseMatches` 只处理真正 stale identity，不再吞 protocol/runtime 错误。

取消 promise 仍立即 settle。worker drain grace 通过 8 Ki、典型大请求和 512 Ki 三档测量，在
200–2,000 ms 内选择有上限的 size-aware grace；不等待用户可见 promise。legacy `format()` fallback
验证失败时构造稳定 failed outcome，禁止重新包装 raw。deadline 的 active-without-worker 理论分支增加
必定 settle 的防御兜底。

editor diagnostics 去重改为排序扫描，不保留同组 O(n²) `some`。DebugEvent 默认把 home/workspace
绝对路径归一化为占位符；`debugDiagnostics` 继续是显式 opt-in，safe report 永不包含 event。

### 2.9 Experimental Hive DDL

experimental 边界继续要求完整消费和全批原子提交，但扩展最常见的已建模子集：

- `CREATE TABLE` column list 后支持有界 `PARTITIONED BY (...)` 与 `STORED AS <identifier>`；
- suffix 顺序、重复项、未知 storage identifier、后续未建模 suffix 仍整条 preserve；
- `formatHiveDdl` 增加可选 options object，支持 `keywordCase`、`commaStyle`、`indentStyle`；现有单参数调用兼容；
- VS Code DDL 命令读取同名 `sqlBeautify.*` 配置，避免主 formatter 与 DDL 固定大写/leading 的冲突；
- range replacement 继承目标首行 indentation，统一处理 target 尾部 horizontal whitespace/newline；
- public DDL diagnostics 使用静态安全 message，内部异常只进 bounded DebugEvent；
- query/DDL 共用 comparator、rejected-result 与 host commit helper，语义 source map 和 DDL delta map 仍分开。

不把 experimental formatter扩成通用 Hive DDL parser；`LOCATION`、`TBLPROPERTIES`、constraints、CTAS
等没有本轮完整语法设计的 suffix 继续 preserve，并在 README 明确列出。

### 2.10 Performance gates

性能主防线改为确定性操作计数，wall time 只保留独立进程的灾难门：

- parser trial、marker validation、source-map query、alignment candidate、diagnostic dedupe 增加可断言计数；
- `tests/v2/perf-baseline.json` 成为唯一 release baseline manifest，包含 version、commit、workload schema，
  两个 relative test 不再各自硬编码 SHA；
- workload 放大到基线中位数至少 100 ms，删除低基线 absolute-delta 分支；
- performance test 只比较时间/RSS/operation counts；跨版本 byte output equality 移到行为测试，使用
  token fingerprint 与版本各自期望，不阻止有意布局变化；
- current 与 baseline 都由当前 project-local TypeScript 编译，删除 package-lock deep equality；
- baseline build 以 manifest SHA 缓存，current 复用一次 canonical build；浅 clone 缺 baseline 时给出明确 skip/error 策略；
- hosted PR 强制执行确定性计数与宽松 disaster gate；严格相对墙钟在 main/manual/nightly 环境执行；
- alignment 的 0.2x 证明改为 candidate/visit counts，墙钟只作为非阻断观测；
-固定 fuzz 继续作为 CI corpus，并支持 `FUZZ_SEED`/`FUZZ_CASES` 探索，失败总是打印 seed/index；
- renderer 精确内部步数断言降为复杂度上界，精确语义只留在对应 unit test。

### 2.11 Build、test 与 release 验证

`build-v2-core` 增加 project-local lock、临时输出和内容 hash stamp：相同 src/tsconfig/toolchain 直接复用；
构建失败保留上一份完整产物并清理临时目录。并发构建得到明确错误，不互删 `.tmp/v2-core`。

测试编排迁到声明式 `scripts/run-v2-suite.js`：功能域定义 command list，现有 `test:v2:wave*` 作为兼容 alias，
`test:verify` 每类 build/typecheck/package step 最多执行一次。新增 `tests/v2/README.md` 的“改动域→targeted suite”
映射，不为命名美观批量重命名历史文件。

发布资产以一个共享 manifest helper 为事实来源；`package.json.files`、clean package、VSIX 和 cutover test
从同一 helper 派生。新增真实加载 `dist/extension.cjs` 的最小 vscode stub smoke。CI 删除重复 clean-package/
VSIX 构建，Node 20 与 Node 24 都跑 core/public smoke，完整 package/performance 只跑一次。

runtime debug build 可选生成外置 source map，但 `.map` 不进 npm/VSIX allowlist；release build failure 明确打印
dist 被保留或清理的状态。`profile-alignment-candidates.js` 补用途/调用说明。

### 2.12 补充审计：DDL protected text、对齐与资源边界

DDL transaction 不得再对 formatter 完整输出执行全局 EOL、尾空白或 continuation-indent 替换。replacement
normalization 必须以 Hive lossless lexer 的 leaf/span 为边界：

- string、quoted identifier、parameter、dialect literal、line/block comment 等 protected leaf 的 raw slice
  逐 code-unit 原样复制；protected slice 内的 LF/CRLF、行尾空格与换行后的字符都不得改写；
- 只允许在 protected span 之外规范化 formatter 生成的 EOL、删除生成的行尾 horizontal whitespace，并且只在
  生成换行之后添加 selection base indentation；protected leaf 内部换行不得触发 continuation indentation；
- lexer diagnostic、span coverage、safe range 或重建一致性任一不能证明时，整笔 DDL transaction 拒绝，不能提交
  部分 edit；LF、CRLF、缩进 selection 与 multi-target 都必须有真实 transaction 回归。

Experimental DDL alignment 复用 core 钉住 Unicode 17 的 display-width authority，不再以 UTF-16 `.length`
决定类型列。`formatHiveDdl` 的可选 options 增加 `maxAlignWidth`，取值范围与主 formatter 相同（1–500），
VS Code DDL 命令桥接同一个 `sqlBeautify.maxAlignWidth`，默认仍为 150。所有 row 先按真实 prefix 起始列测量；
包含换行、无法测量或目标列超过配置上限的名称不参与 alignment，只保留一个必要词法空格。

对齐还必须有独立于视觉上限的线性资源预算：

- generated alignment padding 总量与 source length/row count 线性相关；候选超过预算时整组降级为单空格，不能
  逐行生成与最长 identifier 长度相乘的空白；
- renderer 完成后检查可证明的 output-size budget；超限时 `formatHiveDdl`/`extractDdl` 返回保留原文的静态
  resource diagnostic，transaction 因 non-editable result 保持全批零提交；
- `ExtractDdlOptions.defaultType` 除现有 shape regex 外增加固定 code-unit 上限，避免一个超长 option 值按列数
  重复放大；默认 placeholder 与正常复杂类型不受影响；
- regression 同时覆盖 10k identifier × 1k columns、超长 defaultType、CJK/emoji/combining/tab 名称和正常
  1200-column 性能，断言输出线性上界，而不是只设置 2 GB RSS 灾难门。

`extractDdl` 在 analysis 之前使用与 `formatHiveDdl` 同等级的 plain-data resolver。只接受 undefined 或
prototype 为 `Object.prototype`/`null`、仅含 enumerable data property `defaultType` 的对象；Proxy、accessor、
symbol/未知 key、继承属性和 exotic prototype 都以静态 `EXTRACT_OPTIONS` 失败且不得执行 getter/trap。
合法 data value 再由 `EXTRACT_DEFAULT_TYPE` 执行类型 shape/长度验证。

### 2.13 补充审计：build cache 产物完整性

source hash 只能证明输入未变，不能证明缓存输出仍完整。core/runtime build stamp 升级 schema，并保存按相对路径
排序的完整 output manifest；每项至少包含 byte length 与 SHA-256：

- core manifest 覆盖 `.tmp/v2-core` 中 stamp 之外的全部编译输出；runtime manifest 覆盖当前 debug mode 应生成的
  五件套及可选 map，文件集合必须精确相等且全部为 regular file；
- cache hit 必须逐项复算 size/digest。缺失、增加、截断或任意 byte 变化都视为 cache miss，在 staging 中完整重建；
  旧 schema 只触发一次重建，不提供不校验的兼容路径；
- runtime stamp 写入与 dist 发布失败必须使后续 cache 不可复用；不能把“产物已发布但 stamp 更新失败”当成可通过
  release verifier 的状态；
- `verify-release-artifact --compare-build` 读取可信 build manifest，分别验证当前 dist 与 VSIX entry 对同一 digest，
  不能只证明两份可能同时损坏的字节彼此相等；fresh-checkout 的无 `--compare-build` allowlist/version 验证保持可用；
- negative regression 必须实际删除非入口 core module、改写 runtime artifact、伪造额外文件并验证重建或拒绝；
  `npm run package:vsix` 在损坏缓存后必须先恢复正确产物，直接打包损坏 dist 后 verifier 必须失败。

## 4. 被保留的有意边界

- trailing comma + line comment 的局部 leading fallback 保持，因为改变 source emission 顺序会破坏
  ADR 0002；本轮修的是可发现性，不重开 source-map 重排。
- selection source map 失效时继续拒绝整个 transaction，不以 clamp 掩盖 map 契约破坏。
- debugDiagnostics 仍可能包含错误上下文，但路径默认归一化且配置继续明确说明风险。
- Hive/generic 裸 CJK identifier 继续按 dialect profile preserve；MySQL/PostgreSQL 使用各自证据范围。
- experimental DDL 继续拒绝未完整建模 suffix，不推断字段类型，也不接受部分消费。
- protected literal 内部 EOL 不强制转换为 document EOL；原文保真优先于整份 replacement 的统一行尾。
- U+2028/U+2029/NEL 不升级为 SQL physical newline；这样不会在 string/comment 规则外引入 JavaScript 文本语义。
