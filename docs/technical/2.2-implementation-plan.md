# SQL Beautify 2.2 全量审计整改实施计划

状态：允许实施

设计：[`2.2-audit-remediation-design.md`](2.2-audit-remediation-design.md)

目标：所有审计项完成处置并通过完整回归、性能与打包门后，统一形成一个本地 `2.2.0` 发布候选。

## 1. 执行规则

- 同一 worktree 的 build/test 始终串行；只有互不写共享 artifact 的只读检查可以并行。
- Wave 0 文档提交完成前禁止修改生产代码。
- 每个实现波次先补能在基线上失败的 regression/measurement，再实现，再跑 targeted gate；失败断言
  与所属修复在同一波次提交，任何本地提交都不得让维护测试集保持红色。
- “待验证”项先建立最小复现；证伪时提交契约测试和设计文档处置结果，不为满足审计文字制造行为变化。
- 不通过的 performance gate 必须定位 operation count、workload 或环境原因；不得只放宽阈值。
- 每波只创建一个可解释、可回退的本地提交；跨波次问题使用后续聚焦提交，不 amend 已完成边界。
- package/lock/CHANGELOG 的版本只在最终 release wave 一次性改为 `2.2.0`。
- 本计划授权仓库内代码、测试、文档、stage 和本地提交；不授权 push、tag、Release、workflow dispatch、
  历史改写或删除用户数据。

## 14. 实施结果

状态：实施中；Wave 0–9 已完成，Wave 10–11 仍为 `pending`。

### Wave 0：设计与基线

- 基线：`d81f3a4`，Node `v24.18.0`，Darwin `25.5.0`；
- 80 个去重审计项已进入设计矩阵，终态限制为 `fixed`、`contract`、`withdrawn`；
- commit：`9fc0190 docs(v2): 制定2.2全量审计整改方案`。

### Wave 1：只读复现

- PAR：nested `QUALIFY` depth 10/14/16/18 分别约 47.5/427.3/1370.9/5422.0 ms；
  quoted/template/string 单 leaf callee 均触发 `SYN_INTERNAL_INVARIANT`；
- LAY/TRI：CASE depth 43 可格式化，44/80 返回 `LAYOUT_COMPILE_ARTIFACT`；380 字符字段在
  `maxAlignWidth=500` 下返回 `LAYOUT_PLAN_GAP`；AS/comment 输出可变成 `xxx-- one`/`yy-- c2`，
  comma-first comment 被移到前一 item；
- LEX：`aſ` 被误判 keyword，generic `'x'::int` 产生 `:int` parameter，MySQL `@@session` 拆成
  unknown + parameter，Hive `${a${b}}` 在第一个 `}` 提前终止；U+0085/U+2028/U+2029 按现有
  physical-line 契约不终止 line comment；
- SRC：8000-entry source map 的 100 次 lookup 约 88.8 ms；empty map + nonempty source 的 left
  affinity 返回 `null`，后者确认保持契约；
- ADP/WRK：跨两条语句的 full selection 被 `ADAPTER_RANGE_OWNERSHIP` 拒绝；65 个 producer debug
  event 导致 consumer snapshot 为 `null`；runtime digest mismatch 等满 timeout；malformed worker request
  在 150 ms 内无响应；
- DDL：`PARTITIONED BY`/`STORED AS` 均以 `DDL_UNMODELED_SUFFIX` preserve，`formatHiveDdl.length=1`；
  VS Code adapter 会把 core 的具体非法配置 key 吞成 `null`。

Wave 1 只记录基线事实，不创建代码提交；对应终态由所属实现 Wave 关闭。

### Wave 2：Parser 有界证明与词法保护

- `PAR-01 fixed`：trial 改为 request-local typed key/cache，按 `8 × syntaxLeafCount` 限制 charged
  range work；depth 8/10/14/18/22 的调用数为 16/8/6/6/6，耗时约 1.58/0.93/0.86/0.87/0.93 ms，
  预算耗尽返回 `SYN_PROOF_BUDGET` 并保留 `qualify` identity；
- `PAR-02 fixed`：只有单 leaf code word 参与 collection-name lookup；quoted identifier、template
  parameter、string callee 作为普通 function-call，不再进入 `normalizedWord` 非法域；
- `PAR-03 contract`：registry 未声明 `NULLS LAST`、`OFFSET`、`MINUS` 或 `INSERT ... VALUES`；测试固定
  `ORDER BY`/`LIMIT` 的 expression preserve 以及 `MINUS`/`INSERT VALUES` 的 statement preserve，均不
  伪造 capability identity；
- `LEX-02 fixed`：generic `::` 后缀不再产生 named parameter；
- `LEX-03 fixed`：MySQL `@@name` 成为单个 protected parameter leaf，并沿用 `mysql-variables` identity；
- `LEX-04 fixed`：Hive template scanner 线性跟踪嵌套 `${...}`，外层未闭合时完整 preserve；
- `LEX-05 contract`：U+0085/U+2028/U+2029 固定为非 SQL physical EOL；
- 通过 `npm run test:v2:wave2`、`node tests/v2/lossless-lexer.test.js`、`npm run typecheck:v2` 和
  `git diff --check`；100/800/1200 statement release-relative ratio 为 0.991/1.008/1.023，均低于 1.2；
- commit：本 Wave 聚焦提交 `fix(parser): 限制递归证明并修复保护词边界`。

### Wave 3：Layout、trivia 与资源降级

- `LAY-01 fixed`：layout invariant 只有在全部 failure 都是 `LAYOUT_RESOURCE_BUDGET` 时映射为
  `LAYOUT_COMPILE_RESOURCE`；formatter 对 plan/compiler/renderer 的 typed resource failure 返回 warning +
  preserve，provenance、非法 gap 与其他 artifact 破坏仍 hard fail。CASE depth 43 为 formatted，44/80 为
  preserved，完整原文与 `preserve-target` warning 均已固定；
- `LAY-02 fixed`：`pad-to-column` 保证至少一个显示列；alias target 先完成分组，再把同一 item 的 alias
  位移加入 trailing-comment candidate，AS/comment 双重对齐不再生成零分隔；
- `LAY-03 fixed`：alignment target 同时受 `maxAlignWidth` 和请求级
  `maxGeneratedColumnsPerLine` 约束；380 字符 identifier、`maxAlignWidth=500` 现为 formatted、可重复
  unchanged，不再 poison `LAYOUT_PLAN_GAP`；
- `LAY-04 fixed`：trailing comma 遇逗号前 line comment 时保持 source order 并产生一个去重的
  `LAYOUT_COMMA_FALLBACK` info / `recovery=none`；普通 trailing comma 和 block comment 不误报，README
  配置表已披露。另修复 leading comma 把逗号后 trailing-owned comment 移到 comma-first 行所造成的
  ownership 漂移，corpus/fuzz 严格幂等；
- `TRI-01 fixed`：comma-first comment 仅在左 syntax 与 comma 同行时归左 item，否则 leading 到右 item；
- `TRI-02 fixed`：semicolon 后 footer 在后方空行或 EOF 时归前一 statement trailing；
- `TRI-03 fixed`：terminator 前独立行 comment 归当前 statement dangling，不再 leading；
- `TRI-04 fixed`：canonical renderer fixture 证明 line-comment suffix 后仍可排队后续 suffix；renderer 逐项
  跟踪 physical-line 状态，在后续 suffix 前使用请求 EOL 换行，并只返回最后一个 suffix 是否为未终止
  line comment；
- `DOC-02 fixed`：pipeline statistics 按实际执行累计 first plan/compile/render 与 alignment second
  plan/compile/render，token equivalence 只记最终一次；100/1200 alias 的 leaf/input 系数约
  12.59/12.66、lookup/input 约 18.74/18.87，100/1200 comment 约 13.27/13.36 与 17.65/17.74，
