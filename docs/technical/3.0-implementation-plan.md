# SQL Beautify 3.0 实施计划

状态：执行中

设计：[`3.0-remediation-design.md`](3.0-remediation-design.md)

目标：所有波次完成后统一生成 `3.0.0` 发布候选，不进行中间版本发布。

## 执行规则

- 按下列顺序串行执行波次；同一 worktree 的 build/test 绝不并行。
- 每波先补/调整失败回归，再实现，再运行 targeted gate、typecheck 和 `git diff --check`。
- 每波完成一次只包含该边界的本地提交；提交格式遵循仓库中文 Conventional Commit 规则。
- 审计报告、设计和本计划先提交，之后才允许修改实现。
- 已固定的保守决策直接执行，不等待用户确认。只有外部 push/release、删除用户数据或改写历史会停止。
- 如发现报告断言与代码/实测冲突，以复现证据为准，同步修正文档并继续执行。


另外以独立进程执行 512 Ki worker 延迟/maxRSS、direct 多形态 p95、range validation、
alignment false-positive、source-map entry/clone 与 host multi-selection/DDL 性能门。

最终审查检查：

- 处置矩阵无遗漏；
- 没有 source-map 单调性、安全 snapshot、runtime digest、all-or-nothing 退化；
- 没有未跟踪源码/文档或误纳入 build/package artifact；
- 所有实施提交可独立解释和回退；
- 最终只交付本地 `3.0.0` 发布候选，明确未 push、未 tag、未发布。

不把失败尝试写成已完成事实。
