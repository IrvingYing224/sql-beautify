# ADR 0006：3.0 重构

状态：接受

日期：2026-10-31（3.0.0）

## 背景

2026-10-21 对 2.2.1 做了一次全面审视：黑盒探测 331 个精选用例加 1.3 万个扰动用例，3 万条 fuzz，并分别审查了 core、适配层和工程。2.x 的骨架（无损 lexer → CST → analysis → Layout IR → 单一 renderer → token 等价检查）是对的，实测 token 被改写 0 次、部分提交 0 次。反复出 bug 的原因在别处：

1. **只有安全有规格，排版没有。** 3,640 个 assert 中比对输出文本的约 4%，查出的缺陷却全是排版问题。
2. **要么完整建模，要么原样保留。** 每补一个构造要改 15–18 个文件，`div`、`nulls last`、`limit … offset`、`use db;` 这类日常写法长期得不到格式化。
3. **大量防御在防项目自己的代码。** 调试用 oracle 与契约代码约占 core 的 24.5%；生产路径上对自建对象做 Proxy 检测和来源证明，约占 20% 的 CPU。

## 决定

不换骨架，换重心：先用黄金快照建立排版规格，再删除只防自己的兜底，然后在完整建模与原样保留之间补一层通用排版，最后对照快照修排版缺陷。安全只守五条底线（见 `AGENTS.md`），其余运行时证明全部删除。

所有者确认的决定：

| # | 决定 | 理由 |
| --- | --- | --- |
| D1 | 只保留 Hive 方言，删除 `sqlBeautify.dialect` | 所有者只写 Hive；core 少约 1,700 行，测试矩阵从四份变一份。代价是普通 `.sql` 文件也按 Hive 词法处理，README 写明不要用来格式化非 Hive SQL |
| D2 | 删除 npm 公共门面（`vscode-sql-beautify/formatter` 等子路径导出） | 从未发布 npm，扩展本身不用 |
| D3 | 删除 Copy Safe Diagnostic Report 命令 | 个人使用直接看编辑器诊断即可 |
| D4 | 执行器用一个懒创建的常驻 worker，输入不小于 32 Ki code units 时才用 | 500 KB 输入在宿主线程上会阻塞约 3 秒 |
| D5 | 删除 `sqlBeautify.debugDiagnostics` 与静态安全文案 | 编辑器直接显示原始消息（截断到 200 字符），异常写入输出通道 |
| D6 | 保留 `unsupportedSyntaxPolicy` 三档 | 通用层之后仍有常见的原样保留片段，`preserve` 和 `bail_out` 还有用，代价只有一处检查 |
| D7 | 版本号 3.0.0 | 删除设置是破坏性变更；迁移说明写进 CHANGELOG |
| D8 | 历史文档直接删除，ADR 保留 | git 历史可查；`docs/technical` 降到 600 行以内 |
| D9 | 私有生产语料只在本地用 `--private` 运行，不进仓库 | 所有者可以挑选脱敏样本加入 golden |
| D10 | CI 一个检查 job 加手动发布 job，VS Code smoke 可选 | workflow 从 212 行降到 80 行 |
| D11 | Experimental DDL 的命令名和快捷键不变 | 只做内部合并，不改用户入口 |
| D12 | 主导方可以推送 `claude/*` 功能分支；阶段验收与复核通过后可以快进合入 `main`，不走 PR | 发布和改写历史仍需所有者确认 |
| D13 | `${…}` 模板约定展开值不改变词法结构 | 否则使用 `${hiveconf:…}` 的 ETL 脚本基本都无法格式化；把一个字符串拆在两个变量里的写法不在约定范围内 |
| D14 | `caseLayout` 默认值改为 `compactShort` | 所有者希望短 CASE 收成一行，超过 `caseWhenThenWrapLength` 才展开 |

其他由所有者拍板的排版规则：逗号后紧跟注释时整张列表改用后置逗号（保持前置逗号要改 source map 的顺序契约，登记为 K39）；第一条语句前的缩进作为所有行的基准缩进；展开的 CASE 中 END 与 CASE 对齐，WHEN、ELSE 多缩进一层；关键字后同一行的注释留在关键字行，行注释之后的正文缩进一层；`-- sqlbeautify: off/on` 不做。

明确不做的事（Proxy、provenance 类检查，debug oracle，墙钟性能门，发布字节溯源，没有复现的竞态防御，npm API）写在 `AGENTS.md`，写代码和复核都不再提出。

## 过程

重构分 P0–P8 九个阶段在 `claude/sleepy-allen-pa7396` 上完成，每个阶段经 GPT 复核后快进合入 `main`：

- P0 换用新版 `AGENTS.md`；P1 建立黄金快照与 runner，P1b 补强底线（模板原子、粘连检查）；
- P2 换成 esbuild 构建、单一测试入口和精简的 CI，删除性能门；
- P3 删除 core 中只防自己的检查，对齐第二遍改为改写 plan；
- P4a 重写适配层与宿主，P4b 修适配层的行为缺陷，并执行 D3、D5；
- P5 只留 Hive（D1）；P6 加通用层、命令载荷层、CTAS 与 Hive 数字 literal 等小构造；
- P7 修排版缺陷（K1–K6、K9、K13–K15、K17、K22、K30–K33、K36–K38），执行 D14；P8 重写文档，版本改为 3.0.0。

完整的方案、逐阶段实施记录与复核记录在 P8 删除，最后一版见提交 `PLACEHOLDER` 中的 `docs/technical/3.0-refactor-plan.md` 与 `3.0-refactor-review.md`。

## 结果

| 指标 | 2.2.1 | 3.0 目标 | 3.0 实际 |
| --- | ---: | ---: | ---: |
| `src/` 行数 | 47,573 | ≤ 25,000 | 25,800 |
| `src/core/` | 37,084 | ≤ 22,500 | 22,699 |
| 适配层与宿主 | 8,614 | ≤ 1,500 | 1,621 |
| `tests/` JS 行数（不含 golden 数据） | 33,221 | ≤ 6,000 | 3,796 |
| 构建与检查脚本 | 3,473 | ≤ 200 | 60 |
| 比对输出的用例 | 约 200 | ≥ 1,000 | 1,841 个用例、2,135 个 run |
| `npm test` | 78 步约 138 秒，墙钟门随机失败 | 确定性，≤ 60 秒 | 确定性，约 6 秒（不含构建） |

行数是观察指标，不是验收门；P6、P7 补的构造与排版规则让 `src/` 超出目标约 800 行。

## 后果

- `tests/golden` 是排版行为的唯一规格：改排版先改 golden，纯重构要求 golden 零变化。
- 新增构造只改 parser、layout policy 与 golden，不再需要 oracle 和契约文件。
- 3.0 之后的已知缺陷记在 `sql-formatter-architecture.md` 末尾。
